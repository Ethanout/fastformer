# 选区视觉反馈帧与 HUD（2026-11-14）

## 本阶段改动

- HUD 在帧边界捕获文本、颜色、滚轮反馈和 Gizmo 数值，生成 `HudModel`。`HudFrameRenderer` 只接收模型、字体、图形和本帧布局，不读取输入、会话或时间。
- `InteractionFeedback` 仍由输入环境持有。每帧只推进一次淡出与悬停计时，重复读取冻结结果不会改变后续淡出。
- 两条选区面法线插值归 `SelectionFaceFeedback` 所有。断线、换作用域、清理和无命中都会清除两条通道，修复原先工作区通道遗漏清理的问题。插值仍为 2 tick，仅在面内平滑。
- 几何计划与远端 Gizmo 在帧边界捕获。HUD 复用模型上已有的悬停手柄，避免另做 Gizmo 射线检测。
- 智能选区 HUD 在本帧世界矩阵可用后完成投影和像素滞回，GUI 绘制只消费 `SelectionHudModel`。每帧先清空旧模型，防止隐藏或退出后残留。
- 准星过渡时间在帧边界采样，后处理读取冻结进度；资源创建、失败回退和关闭仍由渲染资源能力负责。
- 新增 HUD 模型／绘制的字节码严格边界，禁止依赖输入、会话、操作控制、几何指针或完整 `Minecraft`。字段、类常量和方法引用的测试防止别名绕过。未扩大债务基线。
- 为 `client.interaction.selectiongesture` 和 `client.interaction.drag` 增加严格能力边界：禁止依赖输入、渲染、会话、操作控制器及完整 `Minecraft`；保留冻结按下事实、工作区数据、模型和类型化变换接口。字节码测试覆盖字段、方法签名、类常量、全局查询及改名的方法引用，架构工具共 11 组测试。
- 增加客户端网络发送严格边界：仅完整类名 `client.network.outbound.ServerGateway` 可以直接依赖 NeoForge 的 `PacketDistributor` 和 `NetworkRegistry`。逐项字节码夹具覆盖字段、泛型签名、类常量和方法引用，验证输入等已有特殊边界不能绕过限制、同名及相邻类没有豁免、服务端不受客户端规则限制。架构工具现有 12 组测试；执行结果由主代理统一记录。

## 保留的边界

旧选区域类型的转换暂留 `FastPlaceClientPreviewCore` 的显式 capture 适配器，仅在 `RenderFrameEvent.Pre` 调用。新增模型、反馈和绘制能力不携带输入会话或全局上下文。Core 的旧世界渲染、模式分发及完整选区模型迁移尚未完成；本阶段不代表总入口已达到 200 行要求。
