# 世界操作历史

历史边界是一次 FastFormer 世界写入任务：快速起形、几何放置、平面填充和操作会话各形成一个批次。近距离交还原版的放置/破坏不进入 FastFormer 历史。

`WorldHistoryManager` 为玩家维护 newest-first 的 undo/redo 双栈。新批次提交时清空 redo；批次数由 `undoHistoryLimit` 限制，默认 200、上限 800。另有 256 MiB 的估算字节预算（undo 与 redo 合计），优先淘汰最旧批次；单个超大批次仍保留，避免刚完成的操作立即不可撤回。

批次只保留每个位置第一次 before 和最终 after。位置使用 packed `long`，方块状态和流体状态使用 palette；统一 before/after 状态省略逐块数组，完整 AABB 还会省略位置数组。方块实体只在存在时复制 NBT。256 MiB 预算按玩家计算，不是全服总预算。

固定方块上限之外还有运行时堆预检：根据当前 JVM 最大堆、已用堆和事务每格估算开销保留至少 256 MiB 或最大堆的八分之一。快照验证前以及 STACK 得到实际复制量后都会复检；空间不足时在写第一格前拒绝操作并提示缩小结构或增加内存。STACK 使用除法式上限判断，不能通过 long 乘法溢出绕过限制。

任务终止后，before deque 和 after map 直接把所有权转交给恢复管理器，不在内存紧张或异常路径再复制一份大型集合。恢复批次压缩前也重新执行堆预检；空间不足时保留原集合、journal 与写入锁等待，不让异常处理本身因第二份快照触发 OOM。

撤回/重做在主线程分批执行。放置、MOVE/STACK 和历史任务共享自适应 tick 预算：每 tick 最多处理 4096 格，同时通常在约 3 ms 后让出主线程；至少推进 1 格，昂贵方块或区块加载不能迫使同一 tick 继续批量工作，也不会让任务永久停滞。写入前必须匹配 expected 状态（含方块实体和流体）；验证或写入期间发现外部修改就停止，并回滚本批已经写入且仍匹配的方块，不覆盖外部方块。恢复快照使用真正禁止邻接反应的客户端同步 flags，避免围栏、墙、楼梯和红石等在相邻格尚未恢复时自行改变，导致精确状态恢复失败。NORMAL 模式只会刷新任务目标集合内部由本任务同步引起的 expected 指纹；发生实际变化时稀疏记录第一次 before 和最终 after，目标边界外仍不纳入历史。任务绑定维度；尚未开始写入时要求玩家回到历史所在维度，开始写入后即使玩家被传送，也只使用批次记录的原 `ServerLevel` 完成写入或回滚。失败任务的部分写入使用同一 expected 检查恢复；恢复遇到外部修改时保留该位置，但继续恢复批次中仍属于本任务的其他位置。

快速起形预计扫描量不超过 16000 时同步生成；超过后由后台生成器持有唯一最终目标集合。生成器只观察进入最终集合的方块，中间扫描线、切片和 SOLID 到 HOLLOW 的临时集合不向外发布。新增目标按 chunk section 聚合，每累计 4096 格发布一批不可变快照供客户端渐进预览；取消通过 generation token 和线程中断停止旧候选继续发布。后台完成前绝不写世界；完成后仍依次执行数量/堆预算检查、before/after 捕获、恢复日志持久化，随后才由 server tick 写第一格。渐进网格构建时保留上一份已完成 VBO，避免频繁候选更新造成预览闪空。生成、放置、undo/redo 和 recovery 都向玩家报告当前进度。

同一服务器维度同时只允许一个 FastFormer 世界写事务进入快照验证、日志准备和写入阶段；几何计算仍可并行。租约以玩家为恢复所有者，部分写入任务取消后直接交给同一玩家的回滚任务，恢复持久化完成前不开放给其他操作。这样后一个 FastFormer 任务不会把前一个任务的未提交中间状态当作自己的可靠 before。异步日志在零写入取消时也先完成删除，再释放租约。

不同玩家仍可在不同维度并行，但同一玩家不能同时持有两个维度事务，因为磁盘层按玩家保证最多一个未提交 `.dat`。玩家切换维度后申请新租约时，会先重试其旧维度的未使用 journal 清理；历史批次跨维度则先释放上一维度再继续。

零写入取消或正常空操作结束时，若未使用的 `.dat` 暂时删除失败，协调器会保留 journal 和维度租约；后续查询或获取租约时先重试清理。删除成功前同一玩家也不能绕过锁继续写入，停服则保留文件交给下一次启动恢复。

停服清空协调器后到达的异步日志回调不能重新登记旧服务器租约；删除未完成时只留下磁盘 journal，由下一次服务器启动处理。

服务器停止清理后和下一次服务器启动恢复前都会等待 FastFormer 单线程日志队列到达空闲屏障，避免同 JVM 重开存档时旧服务器的延迟 `.dat` 在新服务器扫描结束后才落盘。启动事件还会防御性取消任何异常生命周期遗留的静态运行时任务并清空所有旧 server 租约，旧任务不能在新世界的 tick 中复活。

`Ctrl+Z` 先回退活动会话；没有会话但存在生成、验证或分批写入任务时，先取消该任务并恢复已写入部分；否则撤回一批世界历史。左键短按只回退会话，`Ctrl+Y` 重做世界历史。命令为 `/ff undo [int]`、`/ff redo [int]`，容量可用 `/ff undo_history [int]` 调整。批量 undo 遇到未完成任务时，该未提交任务计为第一步；已写入部分和恢复日志完成收敛后再执行剩余次数，避免两个世界写任务并发。任务尚未写入时，也会先等待异步日志清理和维度租约释放，再执行剩余次数。

已完成的 undo/redo 历史在当前服务器进程内按 owner UUID 保留，普通登出不会因退出时机不同而清空已经完成的操作；服务器停止时才清理内存历史。每个 owner 最后生效的 `undoHistoryLimit` 同样保留，因此离线完成的任务不会从用户设置的 800 条错误回落到默认 200 条。放置、MOVE/STACK、撤回、重做和恢复都由服务器 `WorldTaskFeature` 在 server tick 统一推进；任务只保存 owner UUID、维度、冻结参数、阶段、租约和 journal，在线 `ServerPlayer` 只是可选消息观察者。玩家死亡、clone、换维度或断线不会让世界任务失去 tick。离线期间完成或待压缩的记录仍按 owner UUID 进入当前进程历史。正常停服时若任务尚未收敛，磁盘恢复日志继续保留并在下次启动优先处理。

调度顺序固定为恢复/历史、放置、MOVE/STACK。同一 owner 一旦存在恢复任务，后续 writer 暂停；不同 owner 仍受服务器和维度租约约束。旧的玩家 tick 写入入口与断线同步收敛路径已删除，避免同一任务被玩家 tick 和服务器 tick 重复推进。

`writesAllowed` 在 feature 阶段之间和每个 owner 之前重新检查；任一 journal 在当前 tick 关闭总闸门后，列表里的后续 writer 不能借同一 tick 窗口继续写世界。管理器级异常或 OOM 不仅停止本 tick 的后续 writer，还会关闭新写入总闸门直到下次启动恢复扫描；已有 recovery 仍可推进，未知状态下不会继续接受更多世界修改。

逐格写循环内部也检查总闸门，覆盖日志线程在 4096 格批次进行中异步关闭权限的窗口；当前 writer 立即停止并把已写部分交给恢复。

异常或总闸门关闭发生在零写入阶段时，只执行未使用 journal 删除并释放租约；只有已经写入世界的任务才创建恢复批次，避免同一 journal 同时走“已回滚”和“未使用”两套终态协议。

恢复任务不受总闸门阻止；已经接受但尚未完成的普通 undo/redo 在总闸门关闭后转入取消，未写入则清理 journal，已经写入则只执行逆向回滚，不再应用新的历史目标。

玩家离线时只保留每个 owner 最新一条任务 actionbar 和最多四条结果 chat；进度不会逐 tick 堆积。玩家重新登录后交付这些消息，随后清除队列。

玩家断线会放弃尚未完成的普通 undo/redo 请求：未写入时取消并清理未使用 journal，已经写入时由服务器任务继续回滚本次部分变更。由取消放置产生的恢复任务不因玩家断线暂停，仍优先恢复原世界。

所有 FastFormer 世界任务以及 undo/redo 在写第一格前创建 write-ahead recovery journal。日志位于世界目录的 `fastformer-recovery`，成对保存 before 和预期 after，使用位置数组、方块/方块实体 palette 和 gzip，不逐格重复保存相同方块内容；大型日志在后台压缩，写盘完成前不修改世界。放置完成后先分 tick 重新捕获实际写入位置的最终状态；与预测 after 不同的少量位置写入同 stem 的压缩 `.delta`，并携带 base journal 的 SHA-256。delta 与内存 `WorldChangeBatch` palette 都在共享后台提交阶段生成，服务端线程不再为大型结构集中排序和压缩。两者完成后任务才把 `.dat` 原子重命名为 `.done`，因此围栏、墙、楼梯、红石等后续邻居更新后的真实属性同时进入内存历史和崩溃恢复，而不需要重写整份 before。

关卡保存后在独立日志线程等待 NeoForge 区块 IO 真正完成，才删除 `.done` 与对应 `.delta`，不阻塞服务端 tick。若进程崩溃或断电，下一次服务器启动先按全局倒序撤销未提交 `.dat`，再按正序补全已提交 `.done`；base 与 delta 摘要、维度和坐标顺序必须一致。目标状态已存在时跳过，仍为来源状态时写入目标，其他状态作为外部修改保留；恢复/补全完成后强制保存区块，之后才删除整个日志 family。取消或失败回滚同样先强制保存 before，再解除日志。恢复文件损坏、数据版本不一致、维度/方块缺失、摘要不一致或写盘失败时，日志原样保留并禁止新的 FastFormer 世界操作，避免扩大存档风险；没有 `.dat`/`.done` 的孤立 `.delta` 不代表任何事务，可在启动时删除。

启动恢复的 NBT 解码额度同时受 512 MiB 格式上限和当前 JVM 可用堆约束，并保留至少 256 MiB 或最大堆八分之一的余量。若重启时分配的内存不足以安全读取大型 journal，恢复器保留文件并禁用新的 FastFormer 世界写入，不以 OOM 或截断日志换取继续操作。

若回滚已经恢复内存状态、但强制保存或区块 IO 确认失败，任务进入 `RESOLVE` 或仅持久化待恢复阶段并保留维度租约；它按间隔重试持久化，不重复改写方块，也不会提前删除 `.dat`。即使恢复批次压缩后发现世界本来就已处于 before，成功清理 journal 后也必须显式释放租约，失败则重新排队，不能形成无入口的世界写入锁。恢复任务在写回第一格之前被暂停时同样保留原始日志，不能按“零写入的新任务”丢弃。

手动暂停或暂时写入失败的恢复批次会保留为待恢复状态；再次按 Ctrl+Z 或执行 `/ff undo` 才会继续，期间禁止新的世界写入。历史和恢复日志记录 FastFormer 明确写入的方块、流体状态和方块实体 NBT；邻居更新产生的外部副作用、计划刻、玩家库存及原版近距离操作不在记录范围内。FastFormer 替换单格方块时会在该次同步写入调用栈内抑制同位置 `onRemove` 生成的物品实体和经验球，避免 MOVE 或撤回从 NBT 恢复容器、熔炉后留下重复掉落；守卫不影响其他位置、其他实体或原版破坏产生的实体。

Q 暂停只在 owner 在线时保留；owner 断线后，world task 自动重新入队完成恢复，避免一个无人观察的暂停任务长期占用维度租约。

`/ff undo N` 用于继续一个已暂停的未提交任务恢复时，该恢复同样计作第一步；恢复完成后执行剩余 `N-1` 次历史撤回，不因暂停/继续边界丢失命令计数。

方块实体恢复先在世界外创建并完整加载目标 NBT，成功后才一次性替换区块内对象，避免硬崩溃留下半加载实体；替换后发送客户端更新。若一次方块恢复只完成了方块状态、却在方块实体创建或提交时失败，任务会保存该位置的完整实际指纹并在下一 tick 继续恢复。若连实际指纹都无法读取，则维度租约和磁盘日志保持锁定；只有该格之后能被严格证明为批次来源状态或目标状态时才自动继续，无法识别的第三种状态不会被当成 FastFormer 写入覆盖。

无法识别部分写入的 `FAILED` 状态不能被 Q、断线或普通取消当作零写入结束；这些路径都保留 `.dat` 和租约，避免清除唯一的崩溃恢复证据。
