# 选区拖动事件队列

## 实现范围

普通选区的 Gizmo 和面目标现与部件点击共用物理事件队列。键盘、滚轮、按下、释放和替换取消按发生顺序分派。Alt、设点、快速起形及其他会话仍待迁移。

`SelectionPointerEvent` 和 `SelectionPointerCapture` 替代此前只支持部件点击的类型。物理配对编号与业务拖动令牌分开。分派后的按下绑定具体拖动捕获和路由令牌，释放只能结算该捕获。

新按下替换旧按下时，先处理旧捕获的取消，再检查新目标。取消回退旧编辑。如果回退使新目标快照失效，拒绝该快照。旧释放不能提交、取消或清除新拖动。

拖动更新继续在 tick 中读取鼠标射线。面拖动准入仍检查真实世界源数据。本次不修改短按、最终释放位置和锁定规则。同步鼠标路径仍先收取更早的队列事件，该兼容入口尚未删除。

## 自动化范围

`SelectionPointerMailboxTest` 保留原有 8 项点击测试，新增 7 项拖动测试：

- Gizmo 按下与释放在同一批次结束编辑和路由。
- 释放提交对应的 Gizmo 编辑。
- 新按下取消旧编辑，迟到释放不影响新捕获。
- 取消后拒绝基于旧几何的目标快照。
- 旧释放不结算队列外替换的捕获。
- 面拖动释放结算已接受的编辑。
- 面拖动取消恢复基线，迟到释放不提交。

面拖动测试直接建立已接受的捕获，不替代真实世界准入和鼠标命中验收。测试运行结果以 `current_todo.md` 为准。客户端实机、环境切换和连续拖动仍待验收。
