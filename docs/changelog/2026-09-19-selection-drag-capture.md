# 2026-09-19 选区拖动目标捕获

面拖动与 Gizmo 拖动使用 `SelectionDragCapture` 保存会话身份、部件实例身份、按钮和手势令牌。
组拖动固定开始时的目标集合。改变选择集不替换捕获目标。
捕获不保存第二份选中状态，也不持有修改业务状态的回调。

更新与释放都检查会话、手势、目标实例及编辑令牌。
目标删除或编号复用后，旧拖动不能继续修改新对象。
失效捕获取消其编辑，已有编辑令牌检查阻止旧会话取消新编辑。
合法移动保留部件实例身份，因此可以连续更新同一拖动。

新增三项测试，覆盖移动、编号复用、目标删除、组目标删除、会话更换及手势更换。
按钮记录和捕获集合不可变性也有断言。
首次编译因缺少 `List` 导入失败，补齐后重新验证。
全量 `./gradlew test check` 实际执行通过，耗时 32 秒。

这仍是现有输入路径中的捕获迁移。物理事件队列、Gizmo 句柄组件和会话统一捕获管理仍未完成。
真实鼠标释放、对象销毁与断线的实机验收仍待执行。

## 释放路径补充验证

选区拖动释放改用捕获的手势令牌，不再使用全局当前令牌。
失效拖动只释放自己的指针状态。没有选区拖动时，释放入口不结束其他手势。
旧 Gizmo 拖动释放也不再消费新手势的修饰键状态。

新增两项输入入口测试，直接验证迟到令牌不会清除当前令牌，以及空选区释放不会结束点编辑。
测试使用反射访问现有私有入口，没有为测试新增公开业务接口。
补充修改后，全量 `./gradlew test check` 实际执行通过，耗时 37 秒。
