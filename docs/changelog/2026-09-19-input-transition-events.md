# 输入路由事件与切换入口

## 实现范围

- `ClientSemanticEvent` 表达状态观察、提交、提交回执、取消和重置。鼠标、键盘和滚轮尚未全部转换为此类事件。
- `InteractionTransition` 表达保持、拒绝及带原因的切换，不携带任意可执行回调。
- `ClientInputStateMachine.State.onEvent` 判断当前状态能否退出及下一状态。状态机统一执行 `exit` 和 `enter`。
- `inspect` 只读当前状态与请求身份，不保存第二份状态。执行事件时重新检查当前状态，不应用之前检查留下的旧决策。
- 退出使旧手势失效并释放请求归属。进入提交状态时固定请求身份及来源阶段。重置也经过切换入口。
- `ClientRequestTracker` 用单个类型化值保存当前请求，不再并列保存普通放置与选区提交两个身份字段。
- 原接口继续转发到事件入口。现有原版让行、拒绝、取消等待和失败返回阶段规则保持不变。

- `./gradlew test check` 成功。测试实际执行，模组 jar 校验通过。

## 后续迁移

- 此处只统一输入路由和提交门禁的切换。选区设点与快速起形阶段尚未接入完整生命周期。
- 当前入口仍由旧输入代码调用。物理输入的即时拦截、不可变目标捕获和统一事件队列尚未完成。
- 继续分离会话阶段、手势和提交过程，移除旧枚举中的组合职责。完成每轮事件后只调用一次活动阶段的 tick。
- 继续迁移交互组件、候选快照、服务端任务和历史所有权。
