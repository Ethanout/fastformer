# 设计指导思想

用户意图、游戏内证据和几何数学优先。实现结构必须服务于可读性、可测试性和稳定的交互语义。

## 结构原则

- 发现重复、耦合或难以测试的结构时，先暂停并确认原因。
- 相同语义只保留一个实现。只有抽取能减少复杂度时才增加抽象。
- 一个组件只管理一个状态或一个动作。组件通过公开数据协作，不读取彼此的内部字段。
- 输入、命中、反馈、Gizmo、文本和生成数学分开。
- 工作流拥有自己的阶段、模式、参数和生成入口。共享层只放真正同义的动作、约束、预览计划和小型数学工具。
- 会话可以使用以玩家为宿主的状态树或对象盒子。不引入完整 ECS，也不把所有行为塞进万能节点。

## 生命周期原则

- 会话对象绑定玩家 UUID，不绑定会重建的 `LocalPlayer` 或 `ServerPlayer` 实例。
- 重生、换维度和重新连接不自动清空玩家会话。只有取消、完成或显式清理才改变会话内容。
- `inspect()` 只观察状态树的当前路径。它不维护第二份状态。
- 玩家输入先转换为 `SessionSignal`，由当前节点的注册表分发。

## 数据和安全原则

- 近距离输入交给原版。服务端保存世界写入的权威状态。
- 数值先检查有限性，再归一化和限制。写入处再次限制。显示时清理 `-0`。
- 预览、估算和生成使用同一份派生参数。
- 预览命中不能穿过世界首个遮挡面。
- 超出上限时保留边界和操作方向，但不放置不完整形状。
