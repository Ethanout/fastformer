# 状态机运行伪代码

[返回会话树](README.md)

```text
状态处理结果:
    保持
    拒绝(原因)
    切换(目标, 携带数据, 原因, 本地业务动作)

状态:
    enter(来源, 携带数据):
        初始化本阶段
        不判断是否进入，不请求下一次切换

    onEvent(事件):
        判断离散操作
        返回 保持 / 拒绝 / 切换

    tick(本轮输入快照):
        更新持续行为
        判断持续条件是否要求退出
        返回 保持 / 拒绝 / 切换

    exit(原因):
        清理阶段临时资源
        不决定下一状态，不直接调用其他状态
        不因退出就删除整个草稿或全部选区部件

切换请求:
    只是请求，不立即执行 exit
    携带数据在请求时固定，不引用会继续变化的候选
    检查通过前，不提前执行破坏性的业务动作

状态机:
    数据:
        当前状态
        待处理事件队列
        玩家共享数据

    输入回调(物理输入):
        当场判断输入归属
        如果归属原版:
            让行
            返回
        当场拦截原版动作，例如 Q 丢物品
        把语义事件加入队列
        记录按下/释放、修饰键、手势身份、当时的目标信息
        释放事件固定物理释放时间、按钮及对应捕获身份
        入队前核对释放按钮与按下手势的按钮；不匹配则不拦截
        分派释放时核对捕获身份和目标；不匹配则丢弃，不结束新手势
        同一捕获最多结算一次；短按判断使用物理释放时间
        不在回调中切状态或修改草稿

    后台结果回调(结果):
        加入结果事件，附带会话身份和候选版本
        不直接更新当前状态或预览

    每tick():
        本轮事件 = 取走当前队列中的事件
        本轮输入快照 = 读取持续输入

        对于 本轮事件中的每个事件，按入队顺序:
            如果事件的会话、环境或手势身份已失效:
                丢弃事件，释放它持有的结果资源
                继续
            结果 = 当前状态.onEvent(事件)
            应用结果(结果)

        结果 = 当前状态.tick(本轮输入快照)
        应用结果(结果)

        本轮结束
        处理期间新入队的事件留到下一tick
        即使最后发生切换，也不再调用新状态的tick

    应用结果(结果):
        如果结果是保持:
            返回
        如果结果是拒绝:
            显示原因
            返回

        请求 = 结果
        检查目标所需数据和本地业务动作的前提
        如果检查失败:
            保留当前状态与草稿
            显示原因
            返回

        旧状态 = 当前状态
        旧状态.exit(请求.原因)
        应用请求.本地业务动作
        当前状态 = 请求.目标
        当前状态.enter(旧状态, 请求.携带数据)

    切换执行约束:
        只有此入口能够执行状态切换
        检查是只读的，完成检查后才清理旧状态
        exit、本地业务动作、enter只做预先检查的本地操作
        不在切换中等待磁盘、网络、候选计算
        需要等待的操作进入显式等待状态，由结果事件推进
        生命周期异常需要单独恢复，不能把半次切换当成成功

线状态:
    数据:
        第一点
        当前模式
        候选线
        候选版本

    enter(来源, 数据):
        读取第一点和保留的模式
        初始化候选线

    onEvent(事件):
        如果事件是右键:
            如果候选不合法:
                返回 拒绝("候选线不合法")
            返回 切换(
                目标 = 面状态,
                携带数据 = 固定当前候选线,
                原因 = 确认线,
                本地业务动作 = 确认线数据
            )

        如果事件是取消 且当前草稿尚未发送:
            返回 切换(
                目标 = 空闲状态,
                携带数据 = 无,
                原因 = 取消,
                本地业务动作 = 取消当前草稿
            )

        如果事件是候选计算完成:
            如果结果版本不是当前候选版本:
                释放过期结果
                返回 保持
            接收结果
            返回 保持

        返回 保持

    tick(输入快照):
        根据当前模式与持续输入更新候选
        如果某个已定义的持续条件要求结束:
            返回 对应的切换请求
        返回 保持

    exit(原因):
        结束本阶段拖动
        释放本阶段临时资源
        不删除已确认线
        不清空选区部件

本地业务动作:
    确认线数据:
        保存本次固定的线，不重新读取鼠标候选
    取消当前草稿:
        使当前草稿的候选版本失效
        清理本次取消的草稿
        保留其他选区部件和上次模式
    已发送请求的取消:
        不使用上述本地草稿取消流程
        进入服务端取消或恢复流程
        未得到权威结果，不显示已撤回

运行例子:
    本tick开始: 线状态
    本轮事件: 右键、Q
    右键:
        只交给线状态一次
        线 -> 面
    Q:
        交给此时的面状态
        面 -> 空闲
    持续更新:
        只执行一次空闲.tick()
    本tick结束: 空闲状态

不变量:
    任何时刻只有一个活动状态
    同一tick可以按顺序经过多个状态
    同一个事件不会在切换后重新交给新状态
    未注册事件不冒泡
    当前阶段负责正常完成、回退等退出判断
    断线、功能禁用等跨状态条件由上层生命周期处理
    上层也通过统一切换入口，不直接调用exit
    状态树父节点用于组织，不默认逐层调用tick
```
