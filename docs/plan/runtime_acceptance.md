# 运行验收矩阵

这些项目需要开发客户端或真实专用服务器验证。每次测试记录操作 ID、结构方块数、`firstWriteMs`、`afterFirstWriteMs`、总耗时和是否出现错误提示。

## 首块延迟

1. 在空地分别执行 1、16、256、4096 和 32768 方块的小结构。
2. 记录从确认输入到首个可见方块、以及首个方块到完成的时间。
3. 重复每种规模至少 10 次，比较中位数和 P95。
4. 检查首块前没有等待撤回历史压缩；日志中的 `firstWriteMs` 与画面观察一致。

## 状态与取消

1. 在生成、快照、journal、写入、收尾和恢复阶段分别取消一次。
2. 确认每次取消只触发一次动作；部分写入会恢复，未写入时不显示回退进度。
3. 完成后立即执行撤回，确认历史批次可用且方块状态正确。

## 世界生命周期

1. 任务运行时卸载目标维度、切换维度、断线、重连和关闭客户端。
2. 重新进入后确认任务、预览、journal 和恢复任务状态一致。
3. 重启服务器后确认未完成 journal 被恢复，已提交 journal 不重复写入。

## 冲突与边界

1. 写入前后在目标位置进行外部修改，确认冲突提示可理解且外部修改不会被覆盖。
2. 覆盖普通方块、方块实体、流体和会触发邻居更新的方块。
3. 验证 32768、131072、262144 和超过 262144 方块的放置与撤回。

## 结果证据

每项测试保留：复现步骤、结构规模、操作 ID、服务端 metrics 日志、画面状态、最终世界状态和失败阶段。没有这些证据时，不勾选 `current_todo.md` 中对应条目。
