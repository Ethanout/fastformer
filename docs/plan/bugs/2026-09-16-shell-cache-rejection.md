# 外壳缓存拒绝与取消后的输入残留

日期：2026-09-16。分类：程序逻辑、交互体验、异步生命周期。

`BuildingShellCache` 在提交后台任务前保存输入。线程池拒绝任务时，异常直接离开渲染方法，已保存的输入却没有清理。之后相同输入可直接返回旧网格，不再提交任务。

当前任务取消和任务内部抛出取消异常时，同样没有清理输入。被新输入替代的旧任务已经由 `cancelFuture` 移除，因此接收结果时遇到取消，不能一律视为正常替代。

修复：提交被拒绝时先清空无结果的输入，再记录异常。接收当前任务的取消结果也清空输入。普通后台异常先清理缓存，再调用日志回调，避免日志回调异常阻止状态清理。

新增测试覆盖提交拒绝、已取消的 future、包装在执行异常中的取消。每种情况连续请求同一输入两次，确认均可重新提交且不返回旧网格。

修复前测试因提交拒绝异常失败。修复后相关外壳、同步幽灵和异步幽灵缓存测试通过。命令：`gradlew.bat test --tests '*BuildingShellCacheTest' --tests '*GhostMeshCacheTest' --console=plain`。`git diff --check` 通过。

边界：持续失败仍会逐帧尝试，尚无退避。同步外壳构建失败和形状采样异常需要继续检查。未重跑完整测试或实机渲染验收。本页不声明所有渲染异常均可恢复。
