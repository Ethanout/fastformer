# 公共手势误用体素预算与超限提示缺失

日期：2026-09-16。状态：本页两项问题已修复，完整单元测试通过。分组点阵架构仍未完成。

分类：程序逻辑、交互体验、提示缺失、职责边界。

## 已确认问题

`ClientOperationController.updateTransformGesture` 原先对所有公共手势展开每个部件的体素。移动只需更新平移参数，重复调整只需包围盒与重复参数，但它们也受到体素展开上限限制。

复现使用一个 101 × 101 × 101 的重复阵列和另一个小部件。共同移动一步时，代码拒绝展开，平移值仍为零。新增测试在修复前失败。同样的前置检查还会阻止减少重复数量。

公共旋转超限时，原实现只设置 `lastOperationFailureKey`。鼠标拖动入口没有消费该提示，因此用户只看到拖动无效。

## 修复

仅公共旋转为计算旋转中心展开体素。仅公共缩放计算分组选择包围盒。移动不再为这些无关结果分配体素或计算包围盒。

手势更新直接返回可显示的失败提示键。鼠标拖动入口通过 `ClientInteractionFeedback.show` 显示提示。使用编辑令牌限制同次拖动的提示次数，结束、取消和清空工作区时清理记录。

删除更新前无条件恢复基线的步骤。零步手势仍恢复基线，其余更新始终从基线计算新变换。旋转超限在写入工作区之前返回。

这次调整遵循 clean-code 技能的职责分离要求：参数更新不承担无关的体素展开，失败结果由输入入口显示。
