# 分块传输失败隔离

- 状态：已修改代码并添加回归测试。首轮被并行渲染重构的缺失方法阻止。配套实现补齐后，`gradlew test --tests '*IncomingPayloadTransfersTest' --console=plain` 重新编译并执行成功，耗时 21 秒。
- 触发：同玩家的新传输正在接收，另一个传输 ID 的非首分块到达，被接收器拒绝。
- 原因：`FastPlaceNetwork` 异常分支按玩家清理传输，没有匹配失败请求的 ID，误删仍有效的新传输。
- 影响：新传输后续分块无法完成，用户需要重试。工作区与形状入口均受影响。
- 修复：异常清理同时匹配玩家和传输 ID。连接结束的全量清理保留原行为。
- 测试：`IncomingPayloadTransfersTest` 覆盖两种入口的迟到分块、失败清理后继续完成新传输，以及匹配清理不影响另一种传输。
- 边界：测试覆盖接收器与清理组合，网络事件入口使用静态调用核对，尚未进行游戏网络延迟注入。

## 不同玩家的回执作用域互相覆盖

- 触发：两个玩家使用相同传输 ID。传输 ID 来自客户端，不具备跨玩家唯一性保证。
- 原因：传输接收器按玩家隔离，回执作用域 Map 却只按传输 ID 存储。后来的玩家覆盖先前玩家的连接作用域，先前玩家完成时又移除后者的记录。
- 影响：回执可能携带错误玩家的作用域，客户端拒绝合法结果，工作区等待超时。这里不涉及向另一玩家发送方块内容。
- 修复：回执作用域使用玩家 ID 与传输 ID 的组合键，连接清理也按键中的玩家归属执行。
- 收尾：对仍有玩家对象但已经没有回执通道的完成请求，仍移除其作用域记录，避免清理依赖消息能否发送。
- 状态：生产编译通过。测试编译被并行服务端租约迁移阻止（`WorldWriteCoordinatorTest` 仍调用旧 API），已通知服务端任务补齐测试迁移。此前定向测试结果不覆盖这次修改，需重跑。
