# 提交回执实现复核

2026-09-16。以下问题来自正在开发的实现，不代表已发布版本存在这些问题。断线代理正在修正，尚未验收。

## 回执容量

`OperationSubmissionReceiptStore.trim` 保留所有未确认记录。`OperationSubmissionReceiptCodec.encode` 拒绝超过 32 条记录。两者组合后，全部记录都未确认时，新增记录会让保存失败。单次只允许一个提交，不能证明跨断线的未确认记录不会积累。

修复要求：新提交在改变存储前检查容量，给出明确提示，保留已有未确认记录。测试应覆盖全未确认记录达到上限、失败后内存与磁盘一致，以及未知结果跨重连积累的情况。

## 结果隔离与持久化

账本需按服务端实例、维度、玩家和提交编号隔离。进行中查询必须匹配原任务的提交编号，不能仅检查玩家是否有任意任务。已应用结果只能清理同一次提交的草稿，不能清理后续编辑。

草稿和回执分文件写入时，需要处理第二次写入失败。失败补偿不能删除旧草稿，也不能留下看似已发送的新回执。可重试失败、不可重试失败、恢复处理中和未知必须保持不同语义。
