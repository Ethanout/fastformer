# 客户端撤回历史预算审计

## 根因与当前实现

原撤回栈是无界 `Deque<Runnable>`。闭包可以长期持有完整工作区快照和方块数据。

当前实现同时限制记录数量和声明的保留引用单位。默认上限为 512 条、65536 单位。超预算丢弃最旧记录，始终保留最新记录，因此单条记录仍可能超过预算。此机制不是 JVM 字节数的硬上限。

快照声明节点私有引用和共享 payload。共享 payload 按对象 identity 计数，避免不同历史快照对同一数据重复收费。未声明闭包只计一个单位，不能把它解释为真实内存占用。工作区使用状态比较阻止无变化操作进入历史。

## 测试修正

- 删除测试中的 Minecraft `Bootstrap.bootStrap()` 依赖，避免注册表静态初始化干扰普通工作区测试。
- 批量加入两个部件会同时选中它们。撤回选择操作后应恢复 `{1, 2}`，不是 `{2}`。
- 三次加入部件与一次显式 `pushEvent` 共四条历史记录。预算测试原先错误地期望三条。

## 后续入口修复

主代理确认可变 `Retention` 会在释放时使用修改后的权重或 payload 列表，造成记账漂移与引用残留。同一共享对象的不同权重也会使首次收费与最终释放不一致。

现在入栈时复制声明，拒绝负节点单位，并在修改栈前检查当前声明与所有活跃共享对象的单位一致性。清空与最后一次释放会同步清理单位表。新增测试覆盖可变声明与冲突声明的原子拒绝。此修改不改变预算淘汰顺序。
