# 同步幽灵网格缓存的失败提交

日期：2026-09-16。分类：程序逻辑、交互体验、异常边界。状态：缓存修复完成，定向测试通过。

## 原因

`GhostMeshCache.mesh` 原先先替换缓存坐标，再调用网格生成器。如果生成抛异常，新坐标仍留在缓存，但网格仍属于旧坐标。

再次请求相同新坐标会跳过生成，返回旧网格。重新请求旧坐标也会错误地触发重建。确认预览的面与轮廓缓存使用该类。

## 修复

先在局部变量中复制坐标并生成网格。结果非空且生成成功后，再同时替换缓存坐标和网格。异常继续交给调用方，不提交失败结果。

合法的空网格仍可缓存。空引用不是合法网格，拒绝后相同输入可再次生成。

## 验证

新增回归测试在修复前失败。修复后覆盖失败替换保留旧缓存、相同输入重试、空引用拒绝、成功空网格复用，以及清空后的重新生成。

命令：`gradlew.bat test --tests '*GhostMeshCacheTest' --console=plain`。同步与异步缓存测试通过，构建用时 8 秒。`git diff --check` 通过。

本轮没有模拟真实游戏中的生成异常，也没有重跑完整测试。修复保证缓存状态一致，不保证渲染调用方捕获异常后继续运行。持续失败的同步生成仍可能反复抛异常，调用方日志与退避策略需要后续检查。
