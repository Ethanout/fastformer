# 坐标映射冻结导致复制长时间停顿

日期：2026-09-16。状态：已修复本页列出的映射入口，完整单元测试通过。

分类：交互体验、资源成本、集合实现选择。

## 证据

复制测试使用两个各含 110000 格的重复部件。测试先复制一个部件，再尝试复制两个部件并检查累计预算拒绝。修复前该测试耗时 59.388 秒。

独立重跑期间，`jcmd Thread.print` 显示测试线程运行约 35 秒，CPU 时间约 34 秒。栈顶为 `ImmutableCollections$MapN.probe`，调用链经过 `Map.copyOf`、`WorkspacePreviewComposer.compose`、`CompositionBatch.compose` 和 `WorkspaceContentPreparer.clipboardParts`。

该样本直接定位到不可变映射构造中的哈希探测。密集坐标具有聚集的哈希值，JDK 的开放寻址不可变映射在此输入上代价很高。预算虽限制格数，却没有限制这种集合构造成本。

## 修复

新增 `BlockPositionMaps.copyOf`，使用独立的 `LinkedHashMap` 和不可修改视图保存坐标映射。复制时冻结可变坐标，并拒绝空值。

接入体素组合结果、缩放与旋转中间结果、剪贴板、客户端部件、提交计划和选区快照入口。组合结果构造器承担防御性复制，调用方不再先重复冻结一次。

该边界保留不可修改结果和源映射隔离。它不会通过可修改视图绕过历史快照语义。新增测试检查源映射清空、源坐标修改、结果写入、条目改值和键集合修改。

## 验证

修复后同项独立测试耗时 0.977 秒。后续完整测试中该项耗时 0.373 秒。两次测量受预热与运行顺序影响，不作为固定性能承诺。

完整单元测试共 1443 项：1442 项通过，0 失败，0 错误，1 项既有跳过。命令为 `gradlew.bat test --console=plain`，构建用时 33 秒。`git diff --check` 通过。
