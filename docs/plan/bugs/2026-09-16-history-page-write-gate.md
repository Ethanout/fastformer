# 写入暂停时遗留的历史分页请求

日期：2026-09-16。状态：已修复，管理器定向测试通过。

分类：程序逻辑、交互体验、异步任务生命周期。

## 触发与影响

撤销或重做等待历史页时，全局写入开关关闭。原实现只向活动世界任务发送取消请求，没有移除分页调度器中的请求。

如果初始分页尚未创建世界任务，请求继续占用忙碌状态。如果活动任务在等待分页时结束，迟到的页仍可进入缓存。玩家在线且写入限制解除时，接收页的逻辑可能重新发起旧请求。

这不是权限绕过。重新发起请求仍经过操作权限检查。问题是取消后的请求没有失去继续执行的资格。

## 修复

`WorldHistoryManager.tickOwner` 在接收任何历史页之前检查全局写入开关。开关关闭时，先取消分页请求，再执行原有任务取消与回滚路径。

该处理同时丢弃尚未完成的页和已完成但未接收的页。不改变已提交历史，也不承诺立即停止底层磁盘读取。

## 验证与限制

新增 `WorldHistoryOwnerLifecycleTest.closedWriteGateDiscardsPendingAndCompletedPagesBeforeTheyCanResume`。

测试覆盖初始分页与活动任务分页，并分别覆盖未完成与已完成的读取。断言取消后无忙碌状态、页未进入缓存、迟到完成无效，重新开放写入后仍无待接收结果。

修复前该测试失败，原因是关闭写入后仍保留分页请求。修复后，管理器生命周期与分页调度器共 19 项测试通过。

命令：`gradlew.bat test --tests '*WorldHistoryOwnerLifecycleTest' --tests '*HistoryTaskSchedulerTest' --console=plain`。

测试调用真实管理器 tick，但使用空服务端上下文和可控 future。它没有验证在线玩家收到的提示，也没有直接验证真实磁盘读取期间的服务器交互。整个历史架构审计仍未完成。
