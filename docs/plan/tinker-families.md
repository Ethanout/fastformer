# 扳手局部形状与方块家族

状态：扫描和设计完成。局部角块求解已实现，当前规则见 [扳手说明](../tinker.md)。下文保留最初的问题与方案；新增的完整状态扫描见 [候选状态清单](tinker-state-candidates.md)。

## 当前形状算法的问题

`TinkerShapeTransform` 主要根据命中面切换整块、台阶和楼梯。侧面只有上半、下半的判断，没有把点击处映射到局部形状，也没有根据点击区域计算楼梯的内角、外角。因此相邻两个点击位置可能得到相同结果，或带动整块转向。

建议将形状变化改为以下流程：

1. 使用实际形状的射线命中点和命中面，确定玩家点击的局部区域。
2. 将命中面划为四个区域。用 `2×2×2` 的占用格表示整块、上下台阶，以及楼梯的直角、内角和外角。缓存每个可用状态的占用格。
3. 点击凸起处时，在该处凹下；点击凹面时，在该处补起。优先改变命中区域，保留其他区域。选取满足这次局部变化的原版状态。
4. 若有多个状态符合，优先保留原朝向、上下半部和点击区外的形状；再用固定顺序消除平局，避免视角轻微变化引起跳动。
5. 没有对应状态时保持原状，不转成另一种无关形状。预览和实际执行必须使用同一个结果。

这里的四分之一先指一个面的四个区域，每个区域边长为半格。原版整块、台阶和楼梯不能表达任意边长 `1/4` 格的切削；若需要这种精度，必须引入新的方块形状。局部形状求解应限定在原版已有状态内。

不能简单反转任意一个占用格：原版并不具备全部 256 种 `2×2×2` 占用组合。候选集必须来自对应材质的实际方块状态。应测试六个面、四个区域、上下楼梯、内外角、边界命中，以及连续两次操作能否返回原形状。

## 扫描方法与数量

脚本：`tools/analysis/scan_tinker_families.py`。

数据来自本项目 Minecraft Java 1.21.1 的本地源码和资源。没有下载其他版本。

- 扫描源码注册的 **1,060** 个方块 ID；排除 `item_frame`、`glow_item_frame` 两份非方块模型资源。
- 前缀与后缀分开，分别扫描 **3～16 个字符**，不包含 `minecraft:`。
- 前缀得到 **1,692** 个匹配组，按成员集去重后为 **513** 组。
- 后缀得到 **1,611** 个匹配组，按成员集去重后为 **514** 组。
- 提取 **34** 种由多个方块共用的模型条件属性，另按属性名及其取值集合归组。
- 解析模型父级与材质别名，找到 **283** 个由多个方块复用的材质资源。
- 从原版源码直接提取 **84** 条转换：去皮 **21** 条、涂蜡 **36** 条、氧化 **27** 条。

名字和材质只提供候选关系。比如去皮木材与悬挂告示牌复用材质，不应因此自动互转。`shape` 可以表示楼梯形状，也可以表示铁轨形状；`half` 可以表示楼梯上下半部，也可以表示双格植物的上下方块。必须继续比较取值和用途。

当前 slot 扫描读取的是模型的 `variants` / `multipart` 条件，不是运行时完整状态表。不改变外观的属性可能没有列出，例如甘蔗的生长计数。实现时应从注册方块的 `StateDefinition` 读取完整属性和合法取值。

## 建议纳入的类型

| 类型 | 扫描证据 / 例子 | 建议操作 | 保留或联动的内容 |
| --- | --- | --- | --- |
| 整块、台阶、楼梯 | 同材质；`type`、`half`、`facing`、`shape` | 按点击区域局部起伏 | 朝向、上下部、含水；内外角 |
| 原木、木头、去皮变体 | `oak_*`、`*_log`、`*_wood`；去皮映射；侧面材质复用 | 树皮／去皮、端面／全树皮作为两个转换维度 | `axis`；不把旋转和换材质混在同一步 |
| 菌柄、菌核 | `*_stem`、`*_hyphae`、`stripped_*` | 与原木同类处理 | `axis` |
| 竹块、去皮竹块 | `bamboo_block` ↔ `stripped_bamboo_block` | 去皮切换 | `axis`；不虚构全树皮变体 |
| 普通农作物 | 小麦、胡萝卜、马铃薯 `age=0..7`；甜菜、地狱疣 `0..3` | 按实际允许值调整生长阶段 | 方块类型不变；不触发收获或掉落 |
| 特殊植物 | 可可 `0..2`、浆果丛 `0..3`、红树胎生苗 `0..4` | 生长属性独立处理 | 可可朝向、胎生苗悬挂状态 |
| 火把花、瓶子草 | `torchflower_crop`、`torchflower`；`pitcher_crop`、`pitcher_plant` | 成熟需要跨方块类型的规则 | 瓶子草上下格一起处理；不是只改 age |
| 瓜藤 | `melon_stem` ↔ `attached_melon_stem`；南瓜同类；共享藤材质 | 普通藤／连接藤转换 | 年龄与连接朝向需要显式规则 |
| 铜材 | `waxed_*`、`exposed_*`、`weathered_*`、`oxidized_*` | 氧化与涂蜡为两个独立维度 | 台阶、楼梯、门等形状与状态 |
| 紫水晶芽 | `*_amethyst_bud`、`amethyst_cluster` | 小、中、大、晶簇的尺寸循环 | 朝向、含水 |
| 南瓜 | `pumpkin`、`carved_pumpkin`、`jack_o_lantern`；侧面与顶部材质复用 | 普通、雕刻、发光的外观循环 | 首次雕刻确定朝向，后续保留 |
| 铁砧 | `anvil`、`chipped_anvil`、`damaged_anvil` | 损坏程度循环 | 朝向 |
| 珊瑚 | `dead_*`、`*_coral`、`*_coral_fan`、`*_coral_wall_fan` | 活／死切换优先；落地／挂墙需独立规则 | 朝向、含水；不自动重算邻居 |
| 石材外观 | `mossy_*`、`cracked_*`、`infested_*`、`chiseled_*` | 明确配对后转换 | 这些维度不是所有材质都齐全 |
| 数量与填充 | 蜡烛 `candles`、海龟蛋 `eggs`、海泡菜 `pickles`、雪 `layers`、花簇 `flower_amount`、堆肥 `level` | 调整实际允许值 | 属性名称相近不代表相同数量范围 |
| 连接部件 | 栅栏、墙、玻璃板、铁栏杆、菌体、藤蔓 | 命中哪个局部部件，就调整哪个部件 | 墙的低／高连接与栅栏布尔连接分开 |
| 染色家族 | `white_*` 等前缀、`*_wool` / `*_concrete` 等后缀 | 作为可配置外观转换，不默认混入形状操作 | 原材质与朝向；颜色与形状独立 |

## 架构建议

将扳手规则分为三类：

1. **局部形状规则**：点击区域决定凸起、凹陷或连接，覆盖楼梯与连接部件。
2. **状态属性规则**：调整 `age`、`layers`、`candles` 等有明确用途的属性；不遍历并循环所有属性。
3. **类型转换规则**：原木家族、铜材、紫水晶、南瓜等使用明确的有向转换表。

运行时只使用审核过的转换关系。名称扫描用于生成候选配置，不在玩家每次点击时猜测目标。规则由数据包覆盖，可配置操作类型、允许的属性、保留的属性、转换方向、优先级和禁用。

多格植物、门等通过同一次世界事务写入；失败时回滚全部相关位置。沿用现有历史入口，让 Ctrl+Z 恢复全部格子。带方块实体的类型转换必须单独声明数据迁移规则，不能只复制共有属性。

建议顺序：先完成局部形状求解和普通作物年龄，再做木材、铜材、紫水晶与南瓜，最后处理多格植物和其他需要联动的类型。

## 运行与产物

```powershell
python tools/analysis/scan_tinker_families.py
```

默认输出 `.temp/tinker-scan/`：

- `prefix-3-16.csv`：全部前缀匹配。
- `suffix-3-16.csv`：全部后缀匹配。
- `shared-slots.csv`、`shared-textures.csv`：共享属性与材质。
- `vanilla-relations.csv`：原版映射及源码行号。
- `families.json`：完整模型、属性、材质、分组证据。
- `summary.md`：各长度的数量与去重后的完整分组列表。

源码注册与资源清单已相互核对。扫描不修改游戏数据，也不自动启用新扳手规则。
