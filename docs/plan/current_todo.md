- [ ] 为快速起形建立分级预览：小结构保持完整方块预览，中等结构分帧生成/上传，大结构先显示轻量轮廓、边界和密度信息，确认后再生成完整放置数据。测量首帧反馈、帧时间和取消后的恢复时间，避免预览路径构造完整方块实体。
- [ ] 调查观察者方块中键线框填充小结构偶发“JVM 内存不足”：记录内存预约估算、实际驻留、生成阶段和拒绝原因，确认是否为运行时堆配置或错误预算；补充 1、3、16 方块及重复取消/重试测试，修复误拒绝。

## 操作历史磁盘保存与内存预算

设计方向：世界撤回/重做历史由服务端保存和校验，采用磁盘存储加有界内存缓存。客户端只保存可确认恢复的会话草稿，不作为世界历史的权威来源。以下均为待实现任务。

- [ ] 增加服务器全局历史内存预算，覆盖所有玩家的 undo/redo 缓存；核查当前单条超大历史的保留例外，避免把单玩家约 256 MiB 的裁剪目标当成硬上限。离线玩家历史落盘后释放缓存和空闲 OwnerState，避免不同 UUID 长期累积。
- [ ] 为 WorldChangeBatch 设计版本化磁盘格式，保存维度、operation ID、before/after 方块与流体状态及方块实体数据；按存档和玩家 UUID 隔离，保留 undo/redo 顺序，使用稳定的注册名编码并校验格式兼容性。（单批次字节编解码和 UUID 文件往返已验证；顺序索引与历史管理器接入仍待完成。）
- [ ] 异步保存已完成历史，使用临时文件、校验和及原子替换；批次文件与索引更新需具备崩溃一致性。磁盘历史写入不得增加确认到首次落块的前置等待，保存成功后才能释放唯一的历史副本。（已接入完成操作后的后台保存及失败重试，真实文件故障测试通过。尚未把世界 journal 的提交与历史索引更新组成一致的恢复协议；不能启用重启后撤回或缓存淘汰。）
- [ ] 内存仅缓存近期历史，按总字节预算淘汰最久未使用的缓存；旧历史按需异步、有界加载，避免一次解码全部历史。加载期间显示明确状态，不阻塞服务端 tick；重新检查维度、权限和当前世界冲突后才允许撤回/重做。
- [ ] 明确历史存储与故障恢复日志的生命周期边界，优先复用已有编码和分段能力，避免重复保留完整数据。活动任务、pendingRecord、pendingCaptures 及待恢复数据不能因缓存淘汰而丢弃，必须先完成安全持久化或恢复交接。
- [ ] 设置服务器总磁盘配额、单玩家配额和保留期限，提供清理入口；淘汰过期历史时同步更新索引。磁盘满、文件损坏和保存失败时保留可恢复数据并显示准确原因，不把存储失败误报为 JVM 内存不足。
- [ ] 客户端会话草稿按服务器/存档、玩家和维度隔离，记录版本及必要参数；重连后经玩家确认、服务端校验后恢复并重新生成预览。工作区引用失效或对应操作已完成时不得重复提交；不持久化按键、Alt、Future 和旧提交等待。
- [ ] 补充自动化覆盖：多 UUID 上下线后内存有界、超大单条历史、缓存淘汰再加载、undo/redo 顺序、新操作清空 redo、断电式中断各保存阶段、磁盘满/损坏、版本不兼容，以及活动恢复不被淘汰。
- [ ] 实机比较小结构首次落块、近期撤回和磁盘历史撤回的延迟；在重连及服务器重启后核验历史和方块实体完整性，确认后台落盘不会造成明显卡顿。

## Anti-failure 后续任务

来源：[失败滚蛋计划](feature_todo/2026-08-31-anti-failure.md)。会话恢复、预览性能和生命周期验收已在上方列出；这里补充尚未覆盖的阶段任务，原计划保持未完成状态。

- [ ] 复核并完成 PlacementTask 的资源所有权和阶段边界：明确生成、快照、journal、写入、历史发布和恢复交接各自持有的数据及释放条件。先列出现存重复所有权和非法状态组合，只为解决具体问题拆分；覆盖失败、取消与迟到异步完成，避免新增平行状态标记或通用框架。
- [ ] 完成输入、预览和历史管理器剩余职责拆分：输入状态机统一决定动作归属，预览分别管理生成结果、缓存与绘制，历史管理器区分任务调度、存储与缓存。与上方分级预览及磁盘历史任务一起实施，保持世界写入、冲突检查和 Q 取消语义，避免重复改造。
- [ ] 统一失败与等待提示，使用自然、直接的大白话，分别说明原因、当前结果和可执行的下一步。区分临时内存等待、最小工作集不足、磁盘故障、世界未加载、冲突、恢复中和恢复失败；只有实际完成回退后才说“已撤回”，不能一律显示“JVM 内存不足”或“正在回退”。技术原因和 operation ID 保留在日志中。
- [ ] 为提示补充状态对应和网络编码回归：同一失败阶段只能显示与当前任务状态一致的消息；长参数、异常对象和 UUID 不得导致 system_chat 编码断线。实机复核措辞与等待、取消、恢复完成的显示顺序。
- [ ] 汇总普通放置、工作区、选区及撤回/重做的失败矩阵，按生成、首写、后续写入、提交和恢复阶段对应世界未加载、断线、冲突、Q 取消和重启。复用上方自动化与实机条目的证据，只为未覆盖的组合追加测试；明确区分模拟维度不可用、真实进程重启和客户端实测。
