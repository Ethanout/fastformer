## 新功能与体验改善

- [ ] **木框架沿线方向放置。** 快速起形的木框架在线阶段根据已确认线的方向确定放置方向；只有在线方向不可用或没有有效线状态时，才回退到原版点击时使用的木头放置方向。方向计算、预览和最终放置必须共用同一策略，覆盖横向、纵向、斜向、滚轮定线、取消和重新确认。
  - 2026-09-13 静态进展：`WoodFramePlacementEffect`、`SmartWoodFrame` 与 `SmartWoodFrameOrientation` 已让预览和最终解析共用带 guide edge 的轴向策略，`SmartWoodFrameTest` 覆盖直线、拐角、体积边和斜向 tie bias；滚轮定线、取消/重确认仍需客户端验收。
- [ ] **统一交互对象与悬浮文字。** Gizmo 箭头、缩放/堆叠手柄、面、点和其他可指向部件统一实现交互对象接口或通过统一工厂创建。接口至少提供命中范围、交互命令、显示状态、悬浮文字和可用性原因；渲染和输入只消费该对象，禁止各处重复判断和手工补文字。验收每种部件被准星指向时都在准星旁显示正确文字，新增部件若未提供文字配置必须在构建或测试阶段失败，而不是静默缺失。
- [ ] **靠近/远离方块的计时器反馈。** 将当前靠近方块时消失、远离方块时出现的基础计时器调整为 1 秒。新增准星停留加速：准星连续停留在同一方块上的时间越长，正在运行的计时器速度越快；离开目标、目标变更、取消、切换维度和窗口失焦时重置停留累计与加速状态。明确计时器 owner、时间单位、最大加速上限和帧率无关的计算方式，避免重复 tick 或异步回调造成竞态。覆盖快速移入移出、同一方块重复停留、透明/非完整方块和网络延迟。
  - 2026-09-13 静态进展：复制/粘贴输入入口现已对 `false` 显示 actionbar，且中英文资源键已补齐；仍需区分具体失败原因，并核对提交失败和可重试状态的客户端显示。

## 历史与恢复

设计方向：世界撤回/重做历史由服务端保存和校验，采用磁盘存储加有界内存缓存。客户端只保存可确认恢复的会话草稿，不作为世界历史的权威来源。已完成的磁盘格式、后台保存、顺序索引和配额配置见 [更新日志](../changelog/2026-09-11-completed-todo.md)。以下只列剩余实现与验收。

- [ ] 将世界 journal 提交、历史批次和顺序索引更新组成一致的崩溃恢复协议，覆盖各发布边界中断。完成前不能启用重启后撤回或缓存淘汰。磁盘历史写入不得增加确认到首次落块的前置等待，保存成功后才能释放唯一的历史副本。
- [ ] 内存仅缓存近期历史，按总字节预算淘汰最久未使用的缓存；旧历史按需异步、有界加载，避免一次解码全部历史。加载期间显示明确状态，不阻塞服务端 tick；重新检查维度、权限和当前世界冲突后才允许撤回/重做。
  - 2026-09-13 静态进展：`WorldHistoryManager.trim()` 使用饱和加法计算 undo/redo 总字节，避免 long 溢出绕过 256 MiB 淘汰预算（提交 `b1892d6`）。异步加载、实机内存上限和重载验收仍待完成。
- [ ] 明确历史存储与故障恢复日志的生命周期边界，优先复用已有编码和分段能力，避免重复保留完整数据。活动任务、pendingRecord、pendingCaptures 及待恢复数据不能因缓存淘汰而丢弃，必须先完成安全持久化或恢复交接。

## 交互架构与扩展性审计

这些条目是架构约束和验收要求，不表示当前实现已经满足。先以现有状态机、事件入口和配置对象为边界做静态审计，再按已确认的故障拆分；不为抽象本身引入通用状态机框架。

- [ ] **语义事件与阶段状态统一。** 输入层只把键盘、鼠标、中键和滚轮转换为语义事件（例如 `CONFIRM_POINT`、`ADJUST_CANDIDATE`、`SUBMIT`、`CANCEL`）；阶段状态决定事件是否有效、产生什么命令以及下一个状态。Enter 处理不得直接检查具体模式、按钮或历史标记来补特判。
- [ ] **验收案例：滚轮定线后 Enter 提交。** 在 `quick_shape/line` 使用滚轮模式调整候选线并完成定线后，状态必须进入明确的“可提交”语义（可命名为 `READY_TO_SUBMIT`，或由阶段状态提供等价能力）。Enter 对所有可提交状态统一发出提交命令；鼠标确认、滚轮确认、Enter、取消和迟到的预览/提交结果都必须有明确的转换和拒绝规则。覆盖空候选、超上限、快速连续滚轮、Enter 与异步结果同 tick 到达，以及提交失败后的可重试状态。
- [ ] **单一异步 owner 与版本令牌。** 为预览计算、提交回执、取消、换维度、断线和状态观察标出唯一 owner；每次会话/草稿变更生成 revision 或 token。回调只有在 owner、会话、维度和 revision 全部匹配时才能改变状态；迟到结果必须被丢弃并释放资源。取消要有完成态，不能依靠多个平行 boolean 推断“已取消”。
- [ ] **状态机职责边界。** `ClientInputStateMachine` 负责输入归属、手势和取消生命周期；快速起形/选区阶段对象负责阶段转换与确认资格；预览组件负责候选版本和渲染数据；提交组件负责事务请求与回执；反馈组件负责用户可执行的提示。先画出现有调用关系和跨组件写字段，再决定哪些方法应迁移，避免把 `FastPlaceClientInput` 变成新的总控制器。
- [ ] **配置表达行为策略。** 审计 `FastPlaceSettings` 的布尔值、枚举和 NBT 读写：互斥行为用策略枚举或命令能力表示，默认值、版本迁移和运行时读取边界必须明确；输入处理不得组合多个布尔值隐式推导阶段语义。新增“Enter 是否提交”等行为时，配置应能声明策略并由阶段/命令解释，不能在按键入口增加模式分支。
- [ ] **转换表和拒绝原因可测试。** 为每个阶段列出允许事件、状态变化、命令、副作用和拒绝原因；至少为确认、取消、滚轮、异步成功、异步失败、过期结果写状态机测试。测试必须证明非法事件不会改变草稿、预览版本或提交 owner，而不是只检查最终状态。
- [ ] **重复逻辑清理的验收边界。** 任何提取都要保持左键/右键、中键、Alt、原版让行和按下/释放语义；先用行为矩阵证明等价，再删除重复分支。禁止以“统一入口”掩盖不同按钮的确认、拖拽和回退规则。
