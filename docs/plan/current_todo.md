## 会话恢复与预览性能设计

- [ ] 断线重连后显示“发现上次会话，是否恢复”，仅在玩家确认后按维度恢复选区 `min/max`、形状参数、变换参数和工作区引用；不得恢复鼠标按键、Alt、预览 Future 或提交等待。拒绝或换维度时清理客户端瞬时状态；服务端已写入任务继续由恢复日志处理。
- [ ] 为快速起形建立分级预览：小结构保持完整方块预览，中等结构分帧生成/上传，大结构先显示轻量轮廓、边界和密度信息，确认后再生成完整放置数据。测量首帧反馈、帧时间和取消后的恢复时间，避免预览路径构造完整方块实体。
  - [ ] 消除增量收取后的全量集合复制和同步外壳重建；当前 4096 方块收取预算不限制这些后续步骤。按预览版本缓存派生集合与遮挡环境，避免稳定预览每帧复制和全量比较。
  - [ ] 缓存外壳顶点上传结果，减少每帧 CPU 顶点提交；大结构采用轻量预览时避免先生成全部方块再降级。验证连续移动、取消与迟到结果不会显示旧预览。
  - [ ] 实机检查外壳边线静态缓冲的远坐标、颜色、透明度、遮挡及重复取消后的显存释放；面片上传缓存仍待实现，需保留透明面排序。
- [ ] 调查观察者方块中键线框填充小结构偶发“JVM 内存不足”：记录内存预约估算、实际驻留、生成阶段和拒绝原因，确认是否为运行时堆配置或错误预算；补充 1、3、16 方块及重复取消/重试测试，修复误拒绝。

## 操作历史磁盘保存与内存预算

设计方向：世界撤回/重做历史由服务端保存和校验，采用磁盘存储加有界内存缓存。客户端只保存可确认恢复的会话草稿，不作为世界历史的权威来源。已完成的磁盘格式、后台保存、顺序索引和配额配置见 [更新日志](../changelog/2026-09-11-completed-todo.md)。以下只列剩余实现与验收。

- [ ] 将世界 journal 提交、历史批次和顺序索引更新组成一致的崩溃恢复协议，覆盖各发布边界中断。完成前不能启用重启后撤回或缓存淘汰。磁盘历史写入不得增加确认到首次落块的前置等待，保存成功后才能释放唯一的历史副本。
- [ ] 内存仅缓存近期历史，按总字节预算淘汰最久未使用的缓存；旧历史按需异步、有界加载，避免一次解码全部历史。加载期间显示明确状态，不阻塞服务端 tick；重新检查维度、权限和当前世界冲突后才允许撤回/重做。
- [ ] 明确历史存储与故障恢复日志的生命周期边界，优先复用已有编码和分段能力，避免重复保留完整数据。活动任务、pendingRecord、pendingCaptures 及待恢复数据不能因缓存淘汰而丢弃，必须先完成安全持久化或恢复交接。
- [ ] 核验历史存储在现有配额下的磁盘满、文件损坏、版本不兼容和保存失败处理：保留可恢复数据并显示准确原因，不把存储失败误报为 JVM 内存不足。覆盖退休意图、索引替换和批次删除边界的真实进程中断，并测量后台扫描的 I/O 竞争。保留期限、索引同步和活动 owner 保护已完成，记录见更新日志。
- [ ] 客户端会话草稿按服务器/存档、玩家和维度隔离，记录版本及必要参数；重连后经玩家确认、服务端校验后恢复并重新生成预览。工作区引用失效或对应操作已完成时不得重复提交；不持久化按键、Alt、Future 和旧提交等待。
- [ ] 补充自动化覆盖：多 UUID 上下线后内存有界、超大单条历史、缓存淘汰再加载、undo/redo 顺序、新操作清空 redo、断电式中断各保存阶段、磁盘满/损坏、版本不兼容，以及活动恢复不被淘汰。
- [ ] 实机比较小结构首次落块、近期撤回和磁盘历史撤回的延迟；在重连及服务器重启后核验历史和方块实体完整性，确认后台落盘不会造成明显卡顿。
