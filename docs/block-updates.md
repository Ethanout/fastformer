# 方块更新保护

## 放置与交互更新

设置页的“不通知邻居”同时控制几何手放置和创造模式下的方块右键交互。需要启用几何手。

- 拉杆、按钮、活板门、栅栏门等可以改变自身状态，不向邻居传播形状或红石更新。
- 门的上下两半同步开关，但不重算周围栅栏等方块的状态。
- 交互新安排的延迟任务继承该策略，例如按钮弹回。策略随任务保存，重载区块后仍保留。
- 先前已经存在的任务不被追溯修改。普通世界更新和其他玩家的操作继续使用各自的规则。
- 切换回“正常更新”，后续交互恢复原版通知。此前已经安排的受保护任务仍按创建时的策略执行。

客户端预测与服务端使用同一策略，避免客户端先显示邻居状态被改变。

实现通过 Mixin 包装方块交互入口、方块写入、邻居通知和延迟任务，不枚举全部可交互方块。门有一项必要的双半部同步规则。其他模组若直接改区块、另起异步任务或使用自有更新系统，可能绕过这些原版入口。

## 禁止方块下坠

原“全局冻结更新”开关已替换为“禁止方块下坠（全世界）”。默认关闭，需管理员权限修改，设置保存在世界中并作用于所有维度。

开启后，沙子、砂砾、混凝土粉末、铁砧、龙蛋等使用原版 `FallingBlock` 下坠入口的方块不会开始掉落。可疑的沙子和砂砾、脚手架坍塌、钟乳石下坠也受保护。阳光传感器、植物或其他方块引发的更新也不能绕过这些下坠规则。

这条规则不调用 `tick freeze`。时间、实体、植物生长、流体等继续运行。已经成为下落实体的方块继续下落；混凝土粉末接触水后凝固也不受此规则控制。

关闭后，下坠方块在下次收到更新时恢复原版行为，不会扫描整个世界并强制触发掉落。

## 验证

GameTest 覆盖拉杆保护非法邻居状态、正常模式恢复通知、按钮弹回与延迟任务存档、门的双半部同步、异常后的策略清理、混凝土粉末与铁砧下坠拦截，以及世界设置的管理员权限。
