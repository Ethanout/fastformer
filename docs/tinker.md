# 空手方块扳手

开启设置中的“空手右键扳手”后，创造模式空手右键可调整方块。活动会话仍使用自己的按键规则。各方块的普通与下蹲操作见 [设计表](principles/pseudocode/方块扳手-设计表.md)。

本次参考 [Axiom Tinker 文档](https://axiomdocs.moulberry.com/contextmenu/capabilities/tinker.html) 的按部位操作与方块类型转换。以下是几何手的具体规则，并非 Axiom 所有操作的完整复刻。

## 形状转换

完整方块、台阶和楼梯使用同一套局部形状规则。将一格拆为八个边长半格的角块，按实际命中位置决定这次改变哪一个角。

1. 点击外侧凸起表面，挖去点击的角块。
2. 点击内部凹面，补起该面外侧的角块。
3. 在同材质完整方块、台阶和楼梯的合法形态中匹配结果，楼梯包含直形、左右内角和左右外角。
4. 原版无法表示该组合时保持原状。多个状态外形相同，优先保留上下半部与朝向，再使用固定顺序选择。

例如直楼梯挖去一个凸角可变为外角，补起一个凹角可变为内角。完整方块挖去一角变为内角楼梯；单层台阶补起一角变为外角楼梯。

没有材质族的楼梯也可在其已有楼梯形态之间转换。只有台阶变体的材质保留整块与台阶转换，不虚构楼梯。

材质关系来自原版 BlockFamilies，包括木材、石材、石英及各氧化阶段的切制铜。不会通过名称相似度猜测材质。模组方块可通过数据包加入。

台阶与楼梯互转时保留兼容状态，包括含水。填回不支持含水的完整方块后，该格不再含水。Ctrl+Z 可恢复转换前的方块和含水状态，Ctrl+Y 可重做。

客户端与服务端共用目标判定。客户端确认该点击由扳手处理后，跳过原版本地交互预测，等待服务端同步结果。栅栏门中心等交给原版处理的区域仍保留原版预测。

栅栏、墙等仍按点击到的连接部位调整。铁活板门改为切换开关。容器不参与形状转换。

## 木材、草与点击分区

- 原木／木头的横截面切换全树皮，侧面切换剥皮，不改变轴向。菌柄与菌核同样处理。
- 顶面循环“草地 → 草径 → 干耕地 → 草地”，不包含湿耕地。已有湿耕地点顶面后回到草地。草径和耕地的侧面、底面不调整。
- 草地侧面循环“草地 → 灰化土 → 菌丝 → 雪地”，底面不调整。雪地使用带雪外观的草方块，不添加雪层。灰化土、菌丝和雪地点击顶面均变为草径。
- 泥土、砂土、缠根泥土依次循环。矮草、高草下半、高草上半依次循环，只修改点击格，不补另一格。
- 普通火把与点亮的红石火把相互转换。已有熄灭的红石火把不处理。落地和墙上形式分别转换，保留墙上火把朝向。
- 栅栏门顶底面切换嵌墙，窄侧面改变朝向。正背面上下边缘 0.125 格切换嵌墙，左右边缘 0.125 格转向对应侧面。角落优先按上下边缘处理，嵌墙后的上边缘按实际高度判定。其余区域交给原版开关逻辑。
- 墙中央柱存在且点击落在柱体范围内时，先切换中央柱。连接部位继续循环无、低、高连接。
- 通用属性规则仅对外形为完整方块的状态生效。非完整方块只执行已经声明的专用规则。
- 农作物点击任意面循环生长阶段。按原版 1.21.1 模型，胡萝卜、土豆使用 0→2→4→7→0，地狱疣使用 0→1→3→0；自然生长的中间阶段跳到下一个不同外观。其他作物保留全部阶段，不跨类型，只修改点击的一格。资源包可以改变外观。
- 设置中的“农作物跨阶段 age”默认开启；关闭后逐个 age 循环。设置按玩家保存，只影响扳手，不改变自然生长。
- 南瓜梗和西瓜梗未满阶段任意面点击正向生长一级；满阶段顶面回到 0，侧面变为对应附着梗，底面保持不变。附着梗任意面点击恢复成熟普通梗。模组放置种子默认成熟，不生成果实。
- 堆肥桶第 8 阶段点击任意面回到空桶，不产生骨粉；此前阶段保留顶面增加、侧面减少。

木材关系放在 `data/<命名空间>/fastformer/tinker_wood/<名称>.json`，字段为 `log`、`stripped`、`bark` 和可选的 `stripped_bark`。内置八种原木与两种菌柄家族。数据包覆盖同一资源 ID 可替换对应关系，重新加载世界后生效。

## 设置

设置按“操作、外观、历史记录”分类。“操作 → 微操作”包含空手扳手和农作物跨阶段 age。

“操作 → 微操作 → 记录原版放置与破坏”默认关闭。开启后，创造模式普通右键放置（含强制放置）和左键破坏加入世界历史，可用 Ctrl+Z／Ctrl+Y 撤销、重做。一次操作的多格方块及同步邻接变化作为一条记录，保留方块实体数据；无变化或已回滚的操作不记录。

“历史记录 → 微操作压缩策略 → 配置”直接填写三行，按 Enter 或完成时保存：

- 较近历史：超过 **5** 次新操作后，每 **8** 个记录压缩为一组。
- 较远历史：超过 **32** 次新操作后，每 **4** 个记录压缩为一组（已压缩过的较近历史算成一个记录）。
- 遥远历史：超过 **128** 次新操作后，每 **4** 个记录压缩为一组（已压缩过的较远历史算成一个记录）。

“超过”不含阈值本身；三档阈值依次增大。新操作次数按原始次数计算：后来的一组包含 8 次操作，仍计为 8 次新操作。每组记录数则按上一档的组计算：较远档将四组各 8 次压成一组 32 次，遥远档再将四组各 32 次压成一组 128 次，不跨过启用的档位。每条记录在同一档最多压缩一次，不会在同档无限扩大；不足指定记录数时等待。每组设为 1 可跳过该档，后续档接收上一启用档的记录。

扳手及已开启记录的原版放置、破坏共用此策略。默认最新 5 条记录保持独立。原版放置与破坏可以混合成组，不要求方块类型或点击面一致；连续两条记录的 AABB 切比雪夫间距不超过 5 格即可合并。AABB 使用方块坐标的最小／最大值，重叠时距离为 0，否则取三个轴间隔的最大值。压缩后的组同样使用此规则。扳手仍按其分组键和空间相连规则合并。

每条记录创建时缓存 AABB，合组前先对源记录的 AABB 取并集。组内部分操作抵消后仍保留完整包围盒；后续距离比较不扫描组内方块。AABB 独立于渲染模型、轮廓和形状计算，随历史保存；旧记录或缺失、无效的缓存由实际记录坐标重建。完全抵消的组按原规则从历史移除。

合并只处理同维度的连续记录，不跨越其他操作，不改变顺序；方块数、内存限制和快照连续性检查继续生效。后台结果在撤销、重做或修改设置后失效，不覆盖新的历史。关闭记录不删除已有历史。
压缩调度自动观察历史缓存和版本变化，全部重做后会重新检查。后台队列满时保留请求并延迟重试；AABB 也计入内存预算。

玩家配置保存在 `fastformer.tinkerHistoryMerge`，六项为 `recentAfter`／`recentGroup`、`olderAfter`／`olderGroup`、`oldestAfter`／`oldestGroup`。世界的 `fastformer-server.toml` 中，`wrenchHistory.defaults` 使用同名六项作为缺省值，玩家设置优先。旧的空间距离配置重置为这三档默认值；原本三档均停用的配置继续停用。更早的单项记录上限迁移为较近历史的每组记录数，原本停用则三档继续停用。保存时不再写入空间距离或倍率。

## 数据包

新建 `data/<命名空间>/fastformer/tinker_shape/<名称>.json`：

```json
{
  "full": "minecraft:oak_planks",
  "stairs": "minecraft:oak_stairs",
  "slab": "minecraft:oak_slab",
  "priority": 10,
  "enabled": true
}
```

`stairs` 和 `slab` 至少填写一个。目标必须分别是楼梯和台阶，且不能带方块实体。`full` 不能是空气、楼梯、台阶或带方块实体的方块。

数据包规则优先于原版材质关系。同一方块匹配多条规则时，先选较高的 `priority`，相同则按资源标识排序。将匹配规则的 `enabled` 设为 `false` 可停用这些方块的形状转换，不会再次使用原版关系。

规则使用数据包注册表，修改后重新加载世界。其他模组新增的材质关系需要显式配置。

## 验证

GameTest 覆盖六个面的局部角块、四个水平朝向、上下半部、全部楼梯形态、不能表示的对角组合、不同材质、含水、没有材质族的楼梯，以及世界撤销与重做。
